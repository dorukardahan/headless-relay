# Changelog

## [Unreleased]

### Fixed

- Kimi relay on macOS: every run ended with `kimi-relay: refusing: [Errno 3] No such process`, which also hid Kimi's real exit status. macOS answers `getpgid` with ESRCH for an exited-but-unreaped leader and `killpg` with EPERM when that zombie is the only member left; the old code treated both as ownership loss. The relay now proves ownership with `waitid(P_PID, WNOWAIT)`, which only succeeds for its own unreaped child, and accepts EPERM only when `ps` shows no live member in the group. A live member it cannot signal still refuses.

### Documentation and safety

- Kimi preflight: the archived Python `kimi-cli` prints `kimi, version 1.x` and fails this lane with `Output format is only supported for print UI`; the Kimi Code CLI prints a bare version.
- Kimi's free Adagio plan has no Kimi Code access, so native OAuth needs a paid membership; the metered Open Platform API key is the other login.
- Kimi `auto` permissions are the "Never Ask" mode: sensitive-file access and dangerous commands are approved without asking. Only static deny rules still apply.
- Gemini lane refreshed for agy 1.3.4 (live-verified 2026-10-13). Print mode now auto-denies tools (shell, file write, URL read, MCP), but the run still exits 0 with an empty answer, so the examples and the `watch_clip` recipe now treat empty output as a failure. JSON output (`--output-format json`, with `denied_actions`), stdin prompts, the `0s` default `--print-timeout` and the `--effort` rule (base model id only) are documented.
- The model menu is per account: 3.7/3.6 Flash and 3.1 Pro are gone from a personal account, and Gemini 4 Argon (announced 2026-10-13) is for Google AI Ultra and eligible Gemini Enterprise subscriptions only. On an Ultra account, `agy models` lists `gemini-4-argon-high|medium|low`; Argon takes `--effort low|medium|high` only, and 3.1 Pro is missing there too.
- Scenario I adds Gemini 4 Argon as a video lane: in one test it timed speech by sentence, but it also invented on-screen names, so on-screen text needs a frame check.
- The documented agy deadline did not work. agy is a Go binary and Go programs ignore SIGALRM, so `perl -e 'alarm …; exec agy …'` let a run with a 3 s alarm finish after 60 s with exit 0, and agy's own `--print-timeout` returns partial output with exit 0. The new `agy_run SECS …` helper (python3 3.9+) runs agy in a process group led by a small keeper process and, at the deadline, on Ctrl+C, or when agy exits and leaves a child behind, sends the group TERM, then KILL, and exits 124 (130 on an interrupt), so no child process keeps the output pipe open. The keeper is reaped last, so the group id is never signalled after it could be reused; this needs no `waitid`, which the macOS system Python 3.9 lacks. Like the Kimi relay, it resets an inherited ignored SIGCHLD, measures time with a monotonic clock and runs the system `ps` (found on `os.defpath`, not the caller's PATH); if `ps` cannot run, it still sends the group TERM and KILL; the baseline, long-prompt and Party Mode Gemini commands, `agy_image` and `watch_clip` now use it (review follow-up: the baseline command had no deadline at all).
- Party Mode: the Gemini lane now writes `/tmp/ans-gemini.status` (0, 124 for the deadline, 3 for an empty answer from a denied tool) and keeps stderr in `/tmp/ans-gemini.err`, so a silent agy failure is reported instead of leaving an empty answer file. The baseline and long-prompt Gemini examples use the new `agy_answer`, which fails with exit 3 on an empty answer, keeps `agy_run`'s status otherwise (124 for the deadline) and does not print the partial text of a failed run. The reference's image-helper summary no longer says agy writes straight into the output folder; on 1.3.x it needs `agy_image`.
- Gemini CLI wording corrected: it is still released, but its free individual tier rejects the CLI with `UNSUPPORTED_CLIENT`. It needs `GOOGLE_CLOUD_PROJECT` with a Code Assist Standard or Enterprise license, and `--skip-trust` for headless runs in untrusted folders. A Google AI Ultra subscription does not help: a personal Ultra account got the same `UNSUPPORTED_CLIENT` on 0.64.0.
- Video timing limits: a 1-fps watching lane cannot judge sub-second subtitle timing. Use a speech-to-text API with word timestamps for that.
- Gemini image recipe updated for agy 1.3.x: the 1.1.0 `generate_image` prompt now exits 0 with no image, because print mode denies the shell call the model makes instead. The new `agy_image` function uses agy's built-in image-generator subagent, which needs no permission rule. The image lands in agy's own conversation folder, and the function copies it out only after checking that the reported path is inside this run's folder. It never overwrites: it copies to a temporary name in the output folder and hard-links that to the final name, so an existing file or symlink with the same name makes it stop with exit 4 (review follow-up; the first version's plain `cp` replaced such a file and wrote through such a symlink). It also checks for `jq` and creates its temporary file in the output folder before calling agy, so a missing dependency or a missing or unwritable folder stops it with exit 2 instead of after a generated image. The folder check also resolves symlinks: a reported path that leaves the run's folder through a symlinked directory stops with exit 3, where the textual prefix check alone would have let it through. A global rule that triggers an MCP call (for example a memory server in `~/.gemini/GEMINI.md`) also ends a print run empty, so the prompt rules MCP calls out.

## [3.2.0] - 2026-10-13

This minor release includes the accumulated changes since v3.1.1.

### Added

- Native Kimi K3 lane using the first-party Kimi CLI and its own OAuth login, separate from GLM/OpenCode credentials. The wrapper provides an external watchdog, process-group cleanup, physical non-git working-directory checks and an empty skills directory.
- Party / Council Mode instructions for consulting every safely available built-in and custom lane, including independent native subagents. The protocol records replies, failures and skips, preserves dissent, and distinguishes complete bookkeeping from useful success. This is a skill/protocol, not an executable council engine.
- Machine-local model catalog script with a process-group watchdog. It queries installed CLI catalogs rather than maintaining a published account-independent model menu.
- Video-understanding guidance: Gemini through Antigravity can use frames and speech transcription; the documented GLM-5.3-Flash API route uses frames only. The documented Grok route cannot read video. These are prior observations, not fresh inference verification for this release.

### Fixed

- Claude relays leave native model selection to Claude unless an explicit override is supplied. Full model identifiers and printable `[1m]` suffixes remain opaque single arguments; resume and error statuses are preserved.
- Kimi timeout, descendant cleanup, inherited signal handling, cancellation during temporary-directory cleanup, relative paths and PATH/interpreter resolution are guarded. File handoffs accept regular UTF-8 files up to 32 KiB, reject NUL and oversized input before invoking Kimi, and never silently truncate.
- Consensus examples preserve each lane's exit status rather than treating nonempty output as success.

### Documentation and safety

- Updated account-catalog gates and examples for GPT-6 Astra/Sol/Luna, GLM-5.3, Gemini 3.8 Flash and opt-in Grok 4.7. The Grok helper retains its 4.6 default; newer models require per-login catalog verification.
- Documented Claude Opus 5.5 CLI compatibility and served-model verification, separate OpenCode headless-CLI updates, and the ZCode 3.14.5 setup shim.
- Kimi is an explicitly opt-in agentic lane, not a sandbox: global instructions, MCP/hooks, inherited environment and native session/log retention remain active. Subscription handoffs must be direct user-triggered turns, not unattended cron or batch jobs.
- Payload-only Council requests skip lanes whose repository/tool access cannot be safely restricted; asking every model does not grant broader access.

### Verification and limitations

- Offline release gates passed: 356 shipped Claude argv cases and negative mutations; 11 Council documentation/record-rule tests; 18 synthetic Kimi runtime tests; Grok safety and model-pin documentation tripwires.
- The serial Grok synthetic runtime matrix passed 152 cells with zero failures, 82 documented skips and all 43 negative mutations caught. Missing zsh and platform/privilege prerequisites limit coverage; this is not a full three-shell pass.
- No fresh real-provider inference, auth-refresh or egress verification was performed for this release. The unchanged Grok helpers previously had an intermittent cancellation/publication test failure during concurrent testing; serial reruns passed, but its root cause remains undetermined. This release does not claim to fix that observation.
